# T08 — Contacto + form

> v4 brief (2026-11-17). Supersedes the v2 version; DESIGN.md v4 + mockups are the visual authority.

## Goal
The conversion endpoint. A short, honest form that works today as a demo (no data leaves the browser) and becomes a real form on the final host by setting one env variable, without code changes.

## Read first
SPEC §6.6, §4.3 (`form.*`, `cta.*`), DEC-07, DESIGN §3 (ground), §6 (`.channels`, `.form`, `.field`, `.goal-chips`, `.form-status`); canonical markup `design/mockups/src/contacto.body.html`; `src/scripts/site.js` sections 6 and 6b; copy `contacto.json`, `como-funciona.json` (section `que-se-espera`).

## Steps
1. `src/pages/contacto/index.astro`, `BaseLayout` with `hideActionBar`.
   - Hero `section.page-hero.page-hero--v4.bg-weight` (SPEC §3; the mockup and SPEC agree, replacing the older accent-tint): `div.container` > Breadcrumb (Inicio / Contacto, last) > `div.page-hero__grid` > [left: `h1` = copy `h1` through `accent(h1, 5)` (mockup), `p.lead` = copy `lead`; no buttons] + [`div.page-hero__aside` > `Still` settle, objects `lemon-b` (`w 44%, right 4%, top 0, rotate 10`) and `avocado` (`w 34%, left 8%, bottom 0, rotate -10`), container override as page-scoped layout CSS: `.page-hero__aside .still { position: relative; inset: auto; width: 100%; height: 14rem; }`].
2. `section.section.bg-paper` > `div.container.split.split--5-7` (layout: `align-items: start`):
   - Left `aside` (no `aria-label`; the copy has no key for "Canales"): `ul.channels` with three `li.channel`: `span.icon-badge` > Icon (`message-circle`, `mail`, `calendar-days`), `div` > `h3` + `p` from `sections[0].items` (in order). Then `div.panel` (margin layout) > `h3` = `como-funciona.json` section `que-se-espera` `heading` + `p` = its `paragraphs[0]`.
   - Right `div.panel` > `h2` = `sections[1].heading`; `<Note note={{ text: sections[1].disclaimers[0], kind: 'legal' }} boxed icon="shield-check" />`; then the form (step 3).
3. Form `<form class="form" data-contact novalidate data-endpoint={FORM_ENDPOINT} method="post" action={FORM_ENDPOINT || undefined}>` (margin layout):
   - `div.form__row`: Nombre (`fields[0]`, id `f-name`, name `nombre`, `required`, `autocomplete="name"`) and Email (`fields[1]`, `type="email"`, id `f-email`, name `email`, `required`, `autocomplete="email"`). Label text = copy label without the trailing " *", then `<span aria-hidden="true"> *</span>`.
   - WhatsApp (`fields[2]`, `type="tel"`, `inputmode="tel"`, `autocomplete="tel"`) with label and `<span class="field__opt">` = microcopy `form.optional`.
   - Objetivo: `fieldset.field.goal-chips` > `legend.field__label` + one `label.goal-chip` per `fields[3].options` (input `type="radio"` `name="objetivo"`, `span` = option label). Values are kebab-case of the label and MUST include `perdida-de-peso`, `rendimiento` and `clinico` (site.js aliases): Pérdida de peso → perdida-de-peso; Reducción de grasa → reduccion-de-grasa; Mejora de composición corporal → composicion; Ganancia de masa muscular → masa-muscular; Rendimiento o recuperación deportiva → rendimiento; Apoyo nutricional clínico → clinico. First radio checked by default; site.js handles `?objetivo=`.
   - Mensaje: `div.field` > label + `textarea.input` (`fields[4]`, name `mensaje`, `maxlength="1200"`).
   - Hidden `<input type="hidden" name="programa" value="">`; honeypot `<div class="visually-hidden" aria-hidden="true"><label>Empresa<input name="empresa" tabindex="-1" autocomplete="off"></label></div>`.
   - Each required field has `<p class="field__error" id="…-err">` with the SPEC §4.3 text (`form.err.name`, `form.err.email`), and the input has `aria-describedby` pointing to it.
   - Submit: `Button` → `<button class="btn btn--primary btn--block" type="submit">` with the label of `form.submit` and Icon `arrow-right`.
   - `<Note note={{ text: form.notes[0], kind: 'provisional' }} />` only when `!FORM_ENDPOINT`.
4. Status box right after the form: `div.form-status` (`role="status"`, `tabindex="-1"`, margin layout). site.js sets `data-state="success|error"` and focuses it. Inside:
   - `div[data-when="success"]`: Icon `check` (class `icon--l`), `div` > `strong` + `p`. With `FORM_ENDPOINT`: text = `form.ok.live` (no title). Without: title `form.ok.title`, text `form.ok.proto`.
   - `div[data-when="error"]`: Icon `info`, `p` = `form.err.send`.
   - Page-scoped rule (layout only): `.form-status[data-state="success"] [data-when="error"], .form-status[data-state="error"] [data-when="success"] { display: none; }`.
5. If the form posts to a provider (final host), expected providers accept `multipart/form-data` and answer JSON with `Accept: application/json` (Formspree, Getform and Netlify-compatible). Nothing else to do now.
6. No `section.cta-band` and no `data-hide-action-bar` other than the `BaseLayout` prop: the contact page is the destination.

## Tests
- Submit empty: both errors visible, focus on Nombre. Email "ana@": email error visible, with `aria-invalid`.
- Valid submit: green status appears and gets focus; nothing is sent (DevTools network empty).
- `/contacto/?objetivo=deportiva` preselects "Rendimiento o recuperación deportiva"; `?objetivo=medico` preselects Pérdida de peso and sets hidden `programa=B`.
- Build with `PUBLIC_FORM_ENDPOINT=https://httpbin.org/status/500` locally (not committed): error text shown.
- DOM: `.channel` count 3; `.goal-chip` count 6 inside one `fieldset.goal-chips` with a `legend`; no `select`; `.still__obj` count 2 in the hero; no `.cta-band` on the page; `.form-status` hidden before submit.

- Only classes present in components.css; no invented class names.
