# T09 — Blog: content collection, index, article template

> v4 brief (2026-11-17). Supersedes the v2 version; DESIGN.md v4 + mockups are the visual authority.

## Goal
Make the blog ready for the first real article without a code change. The index lists the four teaser ideas from copy as "Próximamente" rows (unlinked, because no article exists) and, when published posts exist, lists them first as linked rows. The article template renders one post with a table of contents, author box and closing section. Drafts are never built. One draft file holds placeholders only.

## Steps

### A. Collection (`src/content.config.ts`)
1. Write exactly:
   ```ts
   import { defineCollection, z } from 'astro:content';
   import { glob } from 'astro/loaders';

   // Test builds only: T11 runs `PUBLIC_INCLUDE_FIXTURES=true astro dev` against tests/fixtures/blog.
   // Default builds read src/content/blog only. process.env (not import.meta.env) because this file runs at config time.
   const fixtures = process.env.PUBLIC_INCLUDE_FIXTURES === 'true';

   const blog = defineCollection({
     loader: glob({
       base: fixtures ? './tests/fixtures/blog' : './src/content/blog',
       pattern: '**/*.{md,mdx}',
     }),
     schema: z.object({
       title: z.string(),
       description: z.string(),
       category: z.enum(['perdida-de-peso', 'deportiva', 'clinica', 'habitos']),
       published: z.coerce.date(),
       updated: z.coerce.date().optional(),
       draft: z.boolean().default(true),
       readingMinutes: z.number(),
     }),
   });

   export const collections = { blog };
   ```
2. No other collection. No `slug` fields (Astro uses `entry.id`).

## Planner notes (contradictions)
1. **Astro 6 content API not verified here.** The brief uses the Astro 5 names (`defineCollection`, `z`, `glob`, `render`, `entry.id`). The worker must check the `astro` types in node_modules. If any name differs, stop and report; do not guess.
2. **Fixture flag replaces the collection source.** With `PUBLIC_INCLUDE_FIXTURES=true` the base changes to `tests/fixtures/blog`, so the draft is absent in that run. Ruling needed if the draft should appear too.
3. **Teaser links conflict with the mockup.** The mockup links teaser titles to placeholder pages. R9 (and this brief) keeps them unlinked, because no article exists. T04 must match.
4. **Blog h1.** The brief takes `blog.json` `h1` ("Artículos en preparación" after overrides). The mockup reads "Ideas editoriales para una futura sección educativa". Confirm which text the copy holds; the mockup's accent (n=3) would apply to it.
5. **Article title accent.** The mockup shows an italic accent ("pérdida de peso"). The template takes a generic title with no per-post accent field, and the schema is fixed here. Add a frontmatter field if a per-post accent is wanted.
6. **Unused blog hero CTAs.** `blog.json` `hero_ctas` are not rendered (the mockup has none). Listed for the T11 allowlist.
7. **Editorial note in the article template** is taken from a teaser's disclaimer. It is right for the prototype (behind `SHOW_EDITORIAL`) but would be wrong for a real article. Decide when the first post ships.
8. **`BaseLayout` `article` prop type.** T03 declares `article?: { published?: string }`. This brief also passes `modified`, which T10 needs. T03 or T10 must widen the type.
9. **OG for posts.** R9 sets `ogTitle` and `ogTag` for posts; T10 must read them from the entry.
